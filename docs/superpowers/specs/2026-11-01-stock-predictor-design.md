# 株価予想アプリ 設計書

- 作成日: 2026-11-01
- 状態: レビュー待ち

## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 目的 | 自分の投資判断の参考にする（個人使用のみ） |
| 対象 | 日本・米国の主要指数 ＋ 登録した個別銘柄 |
| 予測期間 | 翌営業日・1週間後（5営業日）・1か月後（21営業日）を並べて表示 |
| 予測の根拠 | ① 代表的な予測計算式（テクニカル指標）② 世界全体の動向・株式ニュース |
| 費用 | すべて無料の範囲（GitHub Actions / GitHub Pages / Gemini API 無料枠 / Yahoo Finance） |
| 公開形式 | HTML の静的サイト（GitHub Pages） |

### 決定事項と理由

- **ニュース・世界動向は Gemini API の「Google 検索によるグラウンディング」で集める。** Google 検索結果を直接取得（スクレイピング）するのは規約違反でブロックされ、Custom Search JSON API は新規受付が終了しているため。
- **株価の過去データは Yahoo Finance から取る。** 計算式には正確な数値の時系列が必要で、検索結果から取った数値は不正確になりうるため。また `GOOGLEFINANCE` の過去データはプログラムから読めない仕様のため。
- **Apps Script は使わない**（ユーザーの指定）。
- **リポジトリは public。** サイトの URL と JSON データ（公開情報のみ）は誰でも見られる。API キーは GitHub Secrets と、ユーザー自身のブラウザの localStorage にだけ置く。
- **法令面**：個人使用で対価を取らないため、投資助言業の登録対象ではない想定。ただし画面に免責表示を必ず出す。

### 対象

- **指数**：日経平均（`^N225`）、TOPIX（データの都合で TOPIX 連動 ETF `1306.T` で代用。画面には ETF の価格であることを表示する）、S&P500（`^GSPC`）、NASDAQ総合（`^IXIC`）、ダウ平均（`^DJI`）
- **世界の指標**（表示と分析の材料。予測はしない）：ドル円（`JPY=X`）、WTI原油（`CL=F`）、米国10年債利回り（`^TNX`）、VIX（`^VIX`）
- **登録銘柄（初期値）**：IonQ（`IONQ`）

## 2. 全体構成

```
GitHub Actions（毎日 22:00 UTC = 07:00 JST、米国市場の終了後・東証の開始前）
  ├─ ① 株価取得     : Yahoo Finance から約1年分の日足終値
  ├─ ② 世界動向分析 : Gemini（Google 検索付き）→ 点数と理由の JSON
  ├─ ③ 予測計算     : ① と ② を組み合わせ、期間ごとの予測を出す
  ├─ ④ 的中率の更新 : 期限が来た過去の予測を実際の値と照合する
  └─ ⑤ data/ に JSON を保存して commit・push
          ↓
GitHub Pages（site/）
  ├─ data/*.json を読み込んで表示
  └─ 「今すぐ再分析」：ブラウザから Gemini を呼び、② と ③ をその場でやり直す（結果は保存しない）
```

- 言語は JavaScript（ES Modules）に統一する。`src/core/` はブラウザと Node.js の両方で動くよう、外部への依存も Node 専用の API も持たない。
- サイトはビルド不要の素の JavaScript。Chart.js は CDN からバージョンを固定して読み込む。
- Node.js 20。使うパッケージは `yahoo-finance2`、`@google/genai`、テスト用の `vitest` と `playwright`。

### フォルダ構成

```
config/watchlist.json        登録銘柄・指数・指標の定義
config/weights.json          期間ごとの重み（手で調整する）
src/core/indicators.js       SMA・EMA・RSI・MACD・ボリンジャーバンド・回帰の傾き・ボラティリティ
src/core/scoring.js          各指標の値 → −1〜+1 の点数
src/core/predict.js          点数と重み → 期間ごとの予測
src/core/newsSchema.js       Gemini の応答の検査と正規化
src/core/prompts.js          Gemini への指示文（自動処理とブラウザで共有）
src/collector/prices.js      Yahoo Finance から取得
src/collector/gemini.js      Gemini の呼び出し（Node 版）
src/collector/accuracy.js    的中率の照合
src/collector/run.js         毎日の処理の入口
site/index.html, app.js, style.css, gemini-browser.js

```

GitHub Pages には `site/` と `data/` をまとめて公開する（Actions の Pages デプロイを使う）。

## 3. 予測の計算方法

**方式**：点数を重み付けして合計する。各要素の寄与を画面にそのまま示せるので、Gemini に最終判断を任せる方式や機械学習より透明性が高い。

### 3.1 計算式と点数（各点数は −1〜+1 に収める）

| 指標 | パラメータ | 点数の付け方 |
|---|---|---|
| 短期の移動平均 | 5日と25日 | `(SMA5 − SMA25) / SMA25` をボラティリティで割り、tanh で −1〜+1 に圧縮 |
| 長期の移動平均 | 50日と200日 | `(SMA50 − SMA200) / SMA200` を同じように変換。データが200日に満たないときは使わない |
| 75日移動平均との位置 | 75日 | `(終値 − SMA75) / SMA75` を同じように変換 |
| RSI | 14日 | `(50 − RSI) / 50`（売られすぎで＋、買われすぎで−） |
| MACD | 12・26・9 | `(MACD − シグナル) / 終値` をボラティリティで割り、tanh で変換 |
| ボリンジャーバンド | 20日・±2σ | `1 − 2×%b`（下のバンドで＋1、中心で0、上のバンドで−1）。バンドの外側は −1〜+1 で打ち切る |
| 回帰の傾き | 60日 | 日々の変化率に換算した傾きをボラティリティで割り、tanh で変換 |
| ボラティリティ | 20日 | 日々の対数収益率の標準偏差 σd。点数ではなく、予測の幅に使う |

### 3.2 ニュース・世界動向（Gemini）

**呼び出し内容**（自動処理では1日あたり合計 2＋登録銘柄数 回）

1. **世界動向**：米国・日本・欧州・中国・中東・新興国、それに金融政策・為替・資源について、地域ごとの点数を求める
2. **指数への影響**：1 の結果をふまえ、日本市場と米国市場それぞれの点数を、短期（数日）と中期（1か月）に分けて求める
3. **個別銘柄**：銘柄ごとの直近のニュース（決算・業績予想・規制・業界動向）について点数を求める

**応答の形式**（`newsSchema.js` で検査する）

```json
{
  "items": [
    {
      "target": "region:middle_east | market:JP | market:US | ticker:IONQ",
      "score": -0.5,
      "confidence": 0.7,
      "horizon": "short | medium",
      "summary": "要約（日本語）",
      "reason": "株価への影響の理由（日本語）"
    }
  ]
}
```

- `score` は −1〜+1、`confidence` は 0〜1 の範囲で打ち切る。必須の項目が欠けたものは捨てる。
- 参照元の URL は、応答本文ではなく、Google 検索の結果に付く出典情報（groundingMetadata）から取って保存する。
- ニュースの点数 ＝ Σ(score × confidence) / Σ(confidence)。指数には対応する `market:*` の項目だけを使う。個別銘柄には `ticker:*` の項目（重み1）と、その銘柄の上場市場の `market:*` の項目（重み0.5）を合わせて、上の加重平均を取る。

### 3.3 期間ごとの重み（`config/weights.json` の初期値）

| 期間 | 計算式全体 | ニュース全体 | 計算式の内訳 | 使うニュース |
|---|---|---|---|---|
| 翌日（1営業日） | 0.5 | 0.5 | RSI 0.35・ボリンジャー 0.35・短期移動平均 0.15・MACD 0.15 | short |
| 1週間（5営業日） | 0.5 | 0.5 | MACD 0.35・短期移動平均 0.35・RSI 0.15・ボリンジャー 0.15 | short と medium を半分ずつ |
| 1か月（21営業日） | 0.6 | 0.4 | 長期移動平均 0.35・回帰の傾き 0.35・75日移動平均 0.30 | medium |

使えない指標（データ不足）があるときは、残りの指標で重みを按分し直す。ニュースが取れないときは、計算式の重みを 1.0 にする。

### 3.4 予測値

- 合計点 S（−1〜+1）
- 期間の値動き幅 σh ＝ σd × √h（h は営業日数）
- 予想変化率 ＝ S × σh × k（k ＝ 1.0。weights.json で調整できる）
- 予測の幅 ＝ 予想変化率 ± σh
- 方向：S ≥ 0.15 なら「上昇」、S ≤ −0.15 なら「下落」、それ以外は「横ばい」
- 確信度：全要素の点数の符号がどれだけ揃っているか（各要素の重み × 点数の符号が S と一致する割合）で「高（≥0.75）・中（≥0.5）・低」を決める。S ＝ 0 のときは「低」とする

### 3.5 的中率

- 毎日の予測を `data/history/` に保存する。
- 期限（h 営業日後）が来たら、実際の終値と比べて照合する。
  - 方向の的中：横ばいの予測は、実際の変化率が ±σh×0.25 以内なら的中とする
  - 実際の値が予測の幅に入ったかどうか
- 期間ごと・銘柄ごとに集計して `data/accuracy.json` に保存する。
- 重みの自動調整はしない。

## 4. 画面

1ページ構成。スマホとダークモードに対応する。

1. **上部**：最終更新の日時、「今すぐ再分析」ボタン、設定（Gemini API キーの入力。キーは localStorage にだけ保存する）
2. **世界動向**：地域ごとの点数を色付きのカードで表示し、要約と出典リンクを付ける
3. **世界の指標**：ドル円・原油・米国10年債利回り・VIX の現在値と前日比
4. **予測一覧の表**：銘柄・現在値・翌日・1週間・1か月（方向の矢印と予想変化率）・確信度
5. **詳細**（行をクリックすると開く）：価格チャート（移動平均線・ボリンジャーバンド・予測の幅の帯）、点数の内訳、関係するニュース
6. **的中率**：期間ごとの的中率と、予測と実際の比較
7. **フッター**：免責表示「投資助言ではありません。投資の判断はご自身の責任で行ってください。」

**再分析ボタン**：ブラウザから Gemini を呼び（3.2 と同じ指示文）、`latest.json` の株価・指標の値と組み合わせて、`src/core/predict.js` で予測をやり直して表示を差し替える。結果は保存しない。再分析した結果を表示している間は「再分析の結果（保存されていません）」と明示する。

## 5. エラー時の動き

| 状況 | 対応 |
|---|---|
| 一部の銘柄の株価が取れない | 前回の `latest.json` の値を使い、`stale: true` を付けて「⚠️データが古い」と表示する。ほかの銘柄の処理は続ける |
| 株価がまったく取れない | 処理を失敗として終了し、データは更新しない（GitHub から失敗のメールが届く） |
| Gemini の無料枠の上限・通信エラー | 指数関数的な間隔で3回やり直す。それでも失敗したらニュースを使わずに予測し、`newsAvailable: false` として「ニュースの分析なし」と表示する |
| Gemini の応答の JSON が壊れている | 形式の検査に通らない項目は捨てる。全滅したときは上と同じ扱いにする |
| サイトで JSON が読めない | エラーのメッセージと、再読み込みのボタンを表示する |
| ブラウザでの再分析の失敗 | 表示はそのままにして、エラーの内容を通知する |

## 6. テスト

- **`src/core/`**：テストを先に書いてから実装する。既知の数値列で SMA・EMA・RSI・MACD・ボリンジャー・回帰・ボラティリティの計算を確かめる。点数の範囲・重みの按分・方向と確信度の判定・ニュースがない場合のテストも書く。
- **`newsSchema.js`**：正常な応答、項目が欠けた応答、範囲外の値、JSON でない応答で検査の結果を確かめる。
- **collector**：Yahoo と Gemini は擬似データに差し替え、`run.js` が `latest.json`・`history`・`accuracy.json` を正しく書き出すかを確かめる。テスト中に実際の API は呼ばない。
- **サイト**：Playwright で、テスト用の JSON を置いてサイトを表示し、表・チャート・詳細の開閉・データがない場合とデータが古い場合の表示を確認する。

## 7. やらないこと（今回の範囲外）

- 自動売買・証券会社との連携
- 全銘柄の予測
- 機械学習・重みの自動調整
- サイト上での銘柄の追加（`config/watchlist.json` を編集して行う）
- 1日の途中での株価の更新
